2. WHAT IS COMPONENT TESTING?
================================================================================

When we build a React application, we create many small pieces called
"components". For example:
  - MovieCard   --> shows one movie (poster, title, rating)
  - SearchBar   --> the search input box
  - SeatSelection --> the seat grid where user picks seats
  - BookingSummary --> shows the final booking details

Component Testing means we test each of these components one by one to
make sure they work correctly BEFORE we combine them together.

Think of it like this:
  - You build a car.
  - Before putting it together, you test the engine, brakes, and lights separately.
  - That is exactly what component testing does for React apps.

5. IMPORTANT CONCEPTS USED IN TESTING
================================================================================

a) describe()
-------------
   describe() is used to GROUP related test cases together.
   It gives a name to the group.

   Example:
     describe('MovieCard Component', () => {
       // all MovieCard tests go here
     });


b) it() or test()
-----------------
   it() is used to write ONE single test case.
   Each it() block tests ONE specific behavior.

   Example:
     it('renders the movie title on the card', () => {
       // test code here
     });


c) expect()
-----------
   expect() is how we CHECK if something is correct.
   We always combine it with a MATCHER.

   Common Matchers:
     expect(element).toBeInTheDocument()    --> element should exist on page
     expect(element).toHaveTextContent('X') --> element should contain text X
     expect(element).toBeDisabled()         --> element should be disabled
     expect(element).toHaveClass('active')  --> element should have CSS class
     expect(fn).toHaveBeenCalledTimes(1)    --> function should be called once
     expect(value).toBe(150)                --> value should equal 150
     expect(array).toEqual(['A1', 'A2'])    --> array should match exactly


d) render() / renderWithProviders()
------------------------------------
   render() puts the component into a fake browser (jsdom) so we can test it.

   renderWithProviders() is our custom helper that also wraps the component
   with Redux Provider and MemoryRouter (because our app uses Redux and routing).

   Example:
     renderWithProviders(<MovieCard movie={mockMovie} />);


e) screen
---------
   screen is used to FIND elements on the page after rendering.

   Common queries:
     screen.getByText('Jailer 2')           --> find by visible text
     screen.getByRole('button', {name: 'X'})-> find button by name
     screen.getByAltText('poster')          --> find image by alt text
     screen.getByPlaceholderText('Search..')-> find input by placeholder
     screen.queryByText('X')                --> find text (returns null if not found)
     screen.getAllByRole('button')           --> get all buttons on the page


f) fireEvent
------------
   fireEvent simulates user actions like clicking and typing.

   Examples:
     fireEvent.click(button)                         --> simulate a click
     fireEvent.change(input, {target:{value:'Hi'}})  --> simulate typing
     fireEvent.keyDown(element, {key: 'Enter'})      --> simulate key press


g) jest.fn()
------------
   jest.fn() creates a FAKE function.
   We use it to check if a function was called and with what arguments.

   Example:
     const handleSelect = jest.fn();
     fireEvent.click(button);
     expect(handleSelect).toHaveBeenCalledWith(mockMovie);


h) jest.spyOn()
---------------
   jest.spyOn() is used to MOCK (fake) an existing function.
   We use it to fake API calls so tests don't need real internet.

   Example:
     jest.spyOn(movieApi, 'getMovieById').mockResolvedValue(fakeMovieData);


i) waitFor()
------------
   waitFor() is used when we need to WAIT for something async to happen.
   For example, waiting for an API call to finish before checking the result.

   Example:
     await waitFor(() => {
       expect(screen.getByText('Jailer 2')).toBeInTheDocument();
     });


j) preloadedState
-----------------
   Since our app uses Redux, we can pre-fill the Redux store with fake data
   using preloadedState. This helps us test components in specific states.

   Example:
     renderWithProviders(<SeatSelection />, {
       preloadedState: {
         booking: {
           selectedMovie: mockMovie,
           selectedSeats: ['A1', 'A2'],
           totalAmount: 300,
         }
       }
     });

WHAT IS MovieCard?
  MovieCard is a component that displays one movie on the home page.

  Test 1: renders movie title, rating badge, category badge, and metadata

  -------------------------------------------------

  ----------------------------------------------------------
  Click A1 --> ['A1']
  Click A4 --> ['A1', 'A4']
  Click A1 again --> ['A4'] (A1 removed)

  Test 5: Remove button (X chip) removes a seat
  -----------------------------------------------
  We start with seats A1 and A2 selected.
  We click the X button on the A1 chip.
  Result: only A2 remains selected.

  Test 6: Already booked seats are disabled
  -----------------------------------------
  We find any seat with 'booked' CSS class.
  That seat should be disabled (cannot click it).
  Clicking it should not add it to selectedSeats.

8. UNDERSTANDING THE TEST OUTPUT
================================================================================

When you run "npm test -- --verbose", you will see output like this:

  PASS  src/__tests__/MovieCard.test.jsx
    Experiment 1: MovieCard Component
      v renders movie title, rating badge, category badge (354 ms)
      v renders poster image with proper alt text (25 ms)
      ...

Meaning:
  PASS   --> the entire test file passed (all tests in it succeeded)
  v      --> individual test passed (the check mark)
  (Xms)  --> how many milliseconds the test took to run


At the bottom you will see the SUMMARY:
  Test Suites: 8 passed, 8 total
  Tests:       51 passed, 51 total
  Snapshots:   0 total
  Time:        14.28 s
  Ran all test suites.

This means:
  - 8 test files (suites) were run - all 8 passed
  - 51 individual test cases were run - all 51 passed
  - 0 snapshots (we didn't use snapshot testing)
  - Took 14.28 seconds total
